# WorldSeam v0.9.0-dev | 双维度区块驻留和动态同步

版本状态：实验版。支持玩家所在维度与连接的相邻维度同时保留真实 Chunk，但未实现 Immersive Portals 级别的完整同帧场景渲染合成。

## 真实客户端测试中定位的错误

- 旧代码在检查 Chunk 是否需要重新发送之前就调用 target.getChunk()，无人驻留的维度可能反复卸载和重新读取区块。
- 旧的稀疏预览层和准备尚未完成的传送逻辑也额外强制加载目标区块。
- 新增方块更新同步后，在真实客户端 CI 中出现目标服务端驻留 25/25、客户端仅发送 24/25；动态更新包抢占了尚未发送的新 Chunk。

## 本次修复

- 仅在玩家接近跨维连接面时为相邻维度 5x5 视野创建普通（非强制实体刻）Chunk 加载票据；离开、关功能、切换维度及退出会释放。
- 3 级发送优先级严格区分：未发送 -> 真实方块变更 -> 到期低频刷新。纯 Java 5 个单元测试防止饿死、重复发送和移动视野遗漏。
- 3x3 跨维核心加速预热，再扩展到 5x5；预热结束后没有变化就不调用目标 getChunk()，也不继续发送完整 Chunk。
- ServerLevel.sendBlockUpdated Mixin 监听目标维度方块变化，标记已发送 Chunk 为 dirty，最多每 20 tick 合并重新发送原生完整区块、区块实体数据和光照。
- 目标原生 Chunk 准备就绪后暂停重复的稀疏预览和分段样本编码；减少服务器 CPU、包流量和一直加载的文字提示。

## 必须达到的验收条件

GitHub Actions worldseam-dual-world-e2e.yml 真实启动 NeoForge 单人 GUI 客户端，在主世界的玩家位置旁加载地狱：服务器驻留 25/25、客户端独立 ClientLevel 缓存 25/25；在地狱真实修改方块时主世界客户端缓存必须更新；原地静止预热之后不能出现无意义的重复区块强制读取；附带原始截图和日志。失败绝不标注为成功。

## 仍未完成

真实双 LevelRenderer 同帧渲染、无缝连接面裁剪和深度、两侧天空/迷雾/流体/粒子、跨维实体更新和 Mod 物理系统兼容。当前单独的 block-model 代理绘制只能展示部分几何，不能证明真正的视觉无缝。票据暂不强制目标世界实体和随机刻模拟，不能等同于两个完整游戏世界一直模拟。
