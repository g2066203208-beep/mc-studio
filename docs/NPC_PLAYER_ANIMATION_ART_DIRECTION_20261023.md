# NPC 与玩家统一动作｜实机美术审查与整改依据（2026-10-23）

## 结论：初版不通过，不能作为最终游戏演示

唯一可信审查素材是实际 NeoForge Java 21 / MC 1.21.1 GUI 原始 356.4 s 录像、30张截图、客户端日志（Actions [39905868155](https://github.com/g2066203208-beep/mc-studio/actions/runs/39905868155/artifacts/12481416106)）。

观察到：30 个 Actor 及 UUID 在实际世界存在、PlayerAnimator registry 返回30，但镜头指令在真实游戏聊天框报 **`Incorrect argument ... run tp @s`**，镜头仍在多人长焦群像。绝大多数动作只有短促摆臂/摆腿，没有可读的动作弧线；角色仍站在灰石台上，无实际建筑或情境交互。渲染器旧版以服务器独有 entity Tag 识别舞台而未同步到客户端，造成“无一条真实模型动作采样日志”的伪阴性。后续版本加了同步实体布尔状态，只有真实骨骼模型计算差值才算有效，但不能仅凭计数声称美观。

## 与官方艺术参考的关系

**Action & Stuff** 是 Oreville Studios 的 Minecraft Bedrock Marketplace 商业包，强调原版方块角色、连贯的第一/第三人称动画、物品/武器反馈及视觉整体性。参考：Minecraft 官方 Marketplace 商品说明 https://www.minecraft.net/en-us/marketplace/pdp/oreville-studios/actions--stuff-1.12/61c7a786-d7ad-49e0-a710-817121cd9795 。

**Fresh Animations** 是主要针对 Java 版 mob 的资源包，依赖 CEM (OptiFine 或 EMF/ETF)，核心是保留原版外形、给实体自然姿态、面部表达及跟游戏状态变化联动。参考： https://www.curseforge.com/minecraft/texture-packs/fresh-animations 。

**不能复制这两者的受版权保护素材、动画资源、贴图或骨骼文件。** 我们要自行创作可验证的 Minecraft 风格动画，而不是盗用动作数据或声称兼容后就自动具备其效果。

## 首轮纠正（仅此 PR，不能自称全部解决）

1. **15→14 核心动作重创作**：本 PR 重新打关键帧14项（不是全30项已精修），使用多阶段不对称幅度、头部延迟、接触/恢复、非等间距停顿、首尾姿态一致循环；全部原创。
2. 玩家与 NPC 均使用同一 PlayerAnimator `ModifierLayer.replaceAnimationWithFade`，对攻击/受击用2 tick快速转换，走路/跑步约4 tick，放松/恢复约7 tick。防止姿势突变。
3. NPC 完全击晕后的 `PlayerNpcRenderer` 另做完整角色视觉根旋转，使角色在11 tick内逐步横倒，不再仅绕胸腰折叠。**仍需 GUI 与碰撞姿态验收**，不能说具备真实ragdoll。
4. 修复原始镜头的错误嵌套 `facing entity` 指令，改为以固定原点坐标对每人三格近景定位；原始 ffmpeg 视频不断录，分别拍摄开始和稍后时刻的60张截图，以检查身体是否真的动起来；绝不允许截图或日志冒充跑步实体确实位移。
5. GameTest 检查核心14项都具备不少于5阶段、首尾无突跳、原版六关节允许的角度限制。

## 不允许通过的验收边界

- **动画播放 ≠ 好看**；必须审视主观手感及构图、面部/肢体动作质量。
- **原地运动演示 ≠ 实际奔跑**；脚步必须跟真实速度匹配并有对照真实坐标轨迹。
- **上铐姿势 ≠ 有真实约束**；真实架住、背负、牵手必须采用双人 UUID + 可达到的物理空间、碰撞和独立多人同步录屏证据。
- **玩家模型只有六个基本可旋转身体块**；无法单靠手臂pitch转一转做出Fresh级眨眼、肘/膝细分关节、自然物品连接。需要独立美术模型方案/合法资源，不要标记为已完成。
- 真实 GUI 工作流会保存未剪辑 MP4、60张真实相机帧及日志。未确认artifact则不宣布录制成功。
