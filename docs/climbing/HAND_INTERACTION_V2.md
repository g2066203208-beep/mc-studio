# Sable Hands V2 — 双手抓握 + 单手武器 + 视角同步设计

2026-10-20 用户试玩 0.2.0-alpha.1 后的**最新产品决策**。V2 是待实现的正式目标，不是已经开发成功的功能；旧 alpha 仅作原型基线。

## 设计结论：White Knuckle x PEAK，但不是照搬

- 借鉴 White Knuckle 的双手彼此独立占用/抓点/悬挂和物理惯性（由开发者确认左右键各控制一只手）；借鉴 PEAK 的 WASD 易用攀爬、自然攀上边缘和宽容的攀爬辅助。
- 用户明确希望“点击一次抓住，再点一次松开”，**不是**每次都先 G 切换模式或长按左/右键。G 不再是必需步骤；可作为备用/调试/原有输入开关，但正式默认不依赖。
- 用户明确要求在右手抓住墙壁时，左手能拔出手枪单手瞄准/开火/换弹；左/右两手交互和显示均应分别处理，可在第三人称被别人看到。
- 玩家画面继续使用原版 Minecraft 方块状手臂及对应玩家皮肤。可直接重用原版手臂网格/UV，不能把换美术资源当功能解决方案。

## 交互默认草案：先完成这个操作流程

| 玩家状态 | 触发 | 结果 |
|---|---|---|
| 右手空闲 + 面前有效抓点 + 手没有正在使用物品 | 右键点击一次 | 右手 LOCK_GRIP 并固定在表面，松开鼠标不放手 |
| 右手 LOCK_GRIP | 右键再次点击 | 释放右手；不因开火误松手 |
| 左手空闲 + 有效抓点 + 没有持枪 | 左键点击一次 | 左手 LOCK_GRIP |
| 左手 LOCK_GRIP | 左键再次点击 | 释放左手 |
| 右手抓墙 + 左手空闲 | X（可重新绑定） | 左手从装备/物品快捷槽取枪，右手继续悬挂 |
| 右手抓墙 + 左手有枪 | 左键点击 | 武器发射，不触发左手抓点 |
| 左手有枪 | R（武器 API 支持时） | 左手枪械换弹，不改变右手锚点 |
| 左手有枪 | X | 收起枪，左手恢复空闲可抓握 |
| 右手抓墙 + 左手持枪 | WASD、鼠标视角 | 右手受力、角色可按手臂长度及摩擦慢速移动，左手瞄准，后坐力对悬挂身体有可配置的小幅影响 |
| 两手都释放且脚离地 | 物理重力 | 正常坠落，不启用永久飞行/无重力 |

**输入冲突必须严格分优先级：**
1. UI / 菜单与鼠标失焦时，不允许产生新抓点；已锁定抓点不能因为点击菜单而错误释放。
2. **物品优先**：持有武器的手，鼠标按键交给武器 API；不要同时破坏方块、放置物品或抓墙。枪械换弹、装填、射击、瞄准的具体键由适配层路由，不直接吞所有 RMB/LMB。
3. 已锁定抓点的手，指定按键仅释放该抓点；另一只手的操作不触发释放。
4. 空手且满足“可抓几何 + 有明确意图（如靠近攀爬面、空中或蹲下）”时点击抓点；没有抓点时恢复原版手部逻辑，不能全局屏蔽攻击/破坏/放置。
5. 地面向上表面抓握尤其容易与原版采矿/互动冲突，默认要求潜行/低姿态或独立修饰键；保留可配置快捷抓地选项。
6. 如果两只手都忙于持物，不允许抓墙；若左手抓墙时用户要求取枪，先确认右手有效抓握，再释放左手取枪；若右手不抓墙且脚不着地，允许尝试动作但必须真实坠落（不能隐形第三只手）。
7. 高阶用户提供“按住抓握”的 White Knuckle 风格设置，但默认使用点按锁定。
8. 游戏内必须有 2 个小型独立手状态提示（抓握/空闲/持枪/失效）与快捷键重新绑定功能，HUD 可以关闭。

## 每只手独立状态机（核心架构改变）

每手独立：FREE、REACHING、GRABBED_LATCHED、EQUIPPING、HOLDING_ITEM、USING_ITEM、RELOADING、RELEASING、DISABLED。

每只手有独立：
- grip anchor / 在 Sable 子世界中的局部触点与法线、结构 UUID；
- occupied item / 物品槽、动作源、武器适配器、使用中的控制键；
- click latch / 鼠标按键上升沿去抖、重入与事件序号；
- hand pose / 第一人称手臂姿态、第三人称手臂姿态及插值状态；
- grip stamina / 持枪所造成的一手抓握负载（可以后续参数化）。

服务器负责判定抓点及武器状态授权；客户端预测本地动画并平滑校正。网络同步两手 GRABBED/HOLDING_ITEM + 结构 local anchor，给旁观玩家渲染第三人称动作。不要用只在玩家本机运行的 RenderHandEvent 冒充第三人称动画。

## 动作与物理：必须实现的视觉行为（不更换原版美术）

### 第一人称
- **原版两个方块手臂都应可见**：即使原版空副手不会自动渲染，也应在抓握时显式绘制该皮肤对应的原版胳膊，不是更换为新模型。
- 抓住时手臂真正**向前伸向墙体实际命中点**，不能只是渲染时 translate(0.07,0.17,-0.2) 的固定小幅位移。
- 手臂的方向应由相机坐标系中世界锚点的投影驱动（肩 -> 锚点），手随身体和镜头移动保持在抓点位置；Sable 结构转动时抓点持续更新。
- 如果原版一段手臂长无法真实触及，可分成保持原版像素风格与皮肤 UV 的上/前臂两段，但先用简单前伸与腕部摆位验证，再决定是否需要分段骨骼；不引入新皮肤、复杂美术资源。
- 持枪手独立采用枪械自己的原版/Mod物品模型与左手视角，右手仍与墙固定；不能两只手随着一只手的持枪一起播放同一动画。
- 若手枪模型由其他 Mod 强制绑定右手，必须通过适配层/指定枪械 API 验证，不可许诺任意第三方枪械都能直接左手单持。

### 第三人称
- 玩家模型左/右 ModelPart 手臂随对应手状态变化：抓握手指向 **真实世界触点**，持枪手对准视线/目标方向；站立、悬挂、攀上边缘、换弹等不同姿态应区分。
- 用目标点逆算上臂/肩膀俯仰和旋转、身体朝向与相机角度，软插值避免抖动；保持原版 Alex/Steve 手臂形状及皮肤。
- 针对其他玩家也同步关键手状态/动态锚点；服务端断线、死亡、维度、方块消失、Sable 解体时要清状态。
- 为了真正在墙面“悬挂”，必须从玩家碰撞 + 锚点长度 + 重力的求解器得到真实身体位置；不能只把动作画对了，角色其实在原地站立。

## 需求范围及阶段

A. 重新做输入仲裁/点按锁定状态机，移除默认 G 模式依赖与长按式抓握；不破坏原版交互。
B. 第一人称抓点朝向手臂渲染 + 在空副手抓墙时强制渲染原版胳膊。
C. 第三人称两个胳膊、角色悬挂身体姿态、网络同步（包含旁观者）。
D. 右手悬挂 / 左手枪械 **可控兼容示范**，选定实际支持的 NeoForge 1.21.1 枪械 Mod API 后开发；射击、换弹和姿态独立于抓墙。
E. 优化天花板、地板、墙面转角、动态 Sable 局部点、碰撞、惯性及低 TPS。
F. 独立测试客户端录屏验证、GameTests、专用双人服务器和整合包兼容性复测，失败即修复。

## 验收关键场景

1. 空手站在墙边，不按 G，点一下右键右手伸向墙面且锁定；松开按键仍抓墙。再次右键，放手。
2. 左键再抓墙，双手可以不同方块接触；只释放左手，右手不受影响。
3. 右手单手悬挂，按 X 左手取出指定手枪，左键射击；右手锚点不丢失，不误挖方块、也不触发左手重新抓墙。R 换弹时仍能悬挂。
4. 第一人称看得到右手伸到碰撞面的正确接触点，而不是固定摆动；空副手真实显示。
5. 切到 F5 第三人称，能看到右手指向触点、左手持枪；第二个玩家也能看到，且没有手臂漂移。
6. 对天花板、地面、墙壁、Sable 平移/旋转船体分别验证手部锚点与身体位置合法；松手后恢复正常掉落。
7. 不持枪时能正常挖矿、放置、开箱、用盾和吃东西；枪械/其他 Mod 优先级不能把原版操作全禁用。
8. 没有特定枪械 API 前，将枪械兼容性列为**未完成**；只通过 GameTest / 编译不能宣称真正客户端动作体验通过。

## 与旧 alpha 的关系

0.2.0-alpha.1 的 G 模式/鼠标长按、第一人称固定偏移手臂、第三人称无动作是用户已指出的问题；在 V2 目标里都是**待替换的旧行为**，不是最终功能设计。开发 PR 中应根据实际提交记录明确何时迁移完毕。



## 2026-10-20 进一步确定：首个武器试验使用原版弓与原版副手

用户选择先以 Minecraft 原版弓（而非第三方枪械）以及其他单手道具验证单手抓墙/另手操作。**本节是该项目最新的实际实施范围，覆盖上文“按 X 取出手枪”的演示草案。**

- 默认 Minecraft 主手为右、副手为左。把弓放到左手的原版副手槽，可用原版 F 键交换主副手，或直接在背包装备。右手必须为空才能用右键点按锁住墙面。
- 右手抓墙后，左手持原版弓：**左键按住开始拉弓，松开左键发射**，使用原版弓/箭矢数量/耐久、声音与箭实体，不新造武器。
- 同一副手交互分支允许测试普通可使用物品（投掷物、食物、药水等），由原版 Item 使用逻辑决定是否产生效果；无法仅靠一次 use() 支持的复杂道具需另做适配。
- 右键点按锁住或释放右手；左手空手时左键点按锁住或释放左手；不需要 G 进入模式。G 只是**紧急释放双手**。
- 优先级：有左手物品且右手已抓住 -> 左键给左手物品，不抢占成抓握；左手空且有有效碰撞面 -> 左键锁定抓握；右手非空 -> 保留 Minecraft 原本右键操作（除非右手已抓握需放开）。
- 平地顶面的抓握只有蹲下或已离地时自动触发，避免日常左键挖掘、右键使用被频繁劫持。
- 原版弓外观仍是其自己的原版物品模型，不保证真正变成物理单手射箭动画；左手持弓 + 右手锚定的第一/第三人称动作要分别验收。
- 本次代码优先完成输入路由/服务端使用逻辑/隔离测试；实机视觉、真实动态 Sable 船体攀爬与专服是后续独立验收关卡。
