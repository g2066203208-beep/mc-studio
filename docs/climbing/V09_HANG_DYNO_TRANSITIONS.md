# PEAK 0.9 Alpha：真实天花板悬垂、动态表面转角与瞄准蹬墙跳

基线分支：feat/peak-v08-surface-crawl；新实验分支：feat/peak-v09-hang-transition-walljump。
Minecraft 1.21.1，NeoForge 21.1.248，Java21，Player Animator 2.0.4，Sable 2.0.6（在动态结构测试时需要）。

## 用户反馈 → 已修改的实现

1. **天花板像把人横着粘在屋顶**：原因是 `PeakSurfaceRender` 在顶棚时把整个人体沿 X 轴旋转 **64°**，原有顶棚动画也让腿抬起 30–40°。去掉强制 64° 横卧，重绘 3 套顶棚动画：两手向上抬起支撑；胸腹基本保持竖直；两腿向下微屈、重力悬挂；移动时双臂交替探出，身体仅轻微晃动。第一人称另行限制两臂在画面边缘的位置。
2. **墙→顶棚、顶棚→墙、相邻墙、Sable 转角接不上**：`SurfaceProbe.traceTransition` 从眼位和旧抓点外侧同时做射线扇形探测上/下/侧面，允许连贯跨角时更长的抓点差；射线模式统一改用 **COLLIDER 真实碰撞体** 而非 OUTLINE 装饰轮廓。移动时每 tick 做一次转面尝试，缩短转面冷却。在 Sable 中复用 `logicalPose()` 世界⇄子空间映射，转换到世界的物理法线必须匹配。**每 tick 可用会增加射线量，需在真实整合包做性能采样**。
3. **物理化方块攀爬不够稳**：以前只凭 `oldAnchor.dynamic()` 就可能将不同抓点的世界位移误当作结构速度。新增稳定的 `lastResolvedAnchor` 身份对比；只有真正同一个 Sable 局部接触点随船体移动，才可计入严格限幅的船体位移。
4. **在墙上跳向看到的目标**：按住 RMB 挂墙时按 **Space**，服务端按当前镜头朝向与接触面法线计算限幅推离+横向+竖向速度（总上限 0.54 方块/tick），取消旧锚点，7 tick 内禁止立即吸回出发墙，22 tick 墙跳冷却；之后仍按住 RMB、对准新墙即可自动重抓。**Shift** 保留原来的沿墙小冲跃功能。
5. 修改网络协议为 `5`，新增 jump 布尔值，不接收旧版 0.8 客户端 / 服务端混装。服务器校验按键边沿、处于真正墙面抓握与冷却才触发，防止滥发起跳。不能用飞行或穿模替代跳跃。

## 操作

- 空双手 **按住鼠标右键**：抓墙、抓顶棚，松手则恢复普通重力。
- **WASD**：沿当前接触面攀爬；正对墙 W 上爬；顶棚 W 沿锁定朝向前进。
- **Shift**：原有短冲跃（不消耗体力）。
- **Space**：在墙面时朝当前视线方向蹬墙跳；继续按住 RMB 指向新墙，延迟后自动抓。
- **F5**：看第三人称，两臂抓顶、腰腿竖直下垂。

## 验收必须分层

1. CI：Gradle 编译、JUnit、Player Animator 关键帧可解码、普通 Minecraft GameTest、Sable+Player Animator GameTest、图形客户端初启动。
2. 实际游戏：一堵 10 格以上的墙顺畅爬升、转成天花板、沿顶棚匀速横移、转回另一面墙；Sable 平移/旋转/加减速和方块拼接、变形后挂点有效性；F5 看手在头顶与躯干竖直；Space 朝不同方向起跳并接住指定另一堵墙。
3. 必须录第一/第三人称连续视频并实际调整动作关键帧。**CI 通过不等于这些实机目标完成**。先备份存档，独立实例测试，不合并 main，不能宣称 MTS 或 Sable 所有运动面丝滑。

## 已知设计限制

- 每 tick 射线扇形增加碰撞查询成本；真正大型 Sable 物理结构性能有待测量。
- 当前是关键帧+单抓点有界调整，并非两手独立物理 IK；动画垂挂姿态是实质改善，但触点精准度仍需逐帧调整。
- 高速转动 Sable 子空间时，相机贴模/穿插和跨面重抓需要游戏内复测。

### 测试发现并修正（v0.9 第二次提交）

- 原先扩大了完整转面扇形扫描后，在屋顶中央可能把相邻面误认为转角。修正：`SurfaceProbe.nearFaceEdge` 用锚点所在**子世界方块局部坐标**判断是否靠近可转面边缘（忽略当前面的法线轴），在屋顶中央不会强制探测新墙；靠近边角才运行昂贵扇形射线。新增 GameTest 验证墙/顶的中心与边缘分类。
- 原墙跳 GameTest 初始视线瞄得高于唯一测试墙块导致起跳前就没有真实抓点，改为**先正视成功抓墙，再抬头瞄目标并触发 Space**。仍然必须验证起跳后的离墙速度与短暂防重新吸回。
