# PEAK v0.11 — 动画正常恢复、自然悬挂与蹬墙跳

基于 v0.10（PR #20）的独立实验修复。Minecraft 1.21.1 / NeoForge 21.1.x / Player Animator 2.0.4；Sable 2.0.6 为动态方块测试依赖。

## 从真实代码确认的故障

1. 旧版 `PeakAnimationController` 用区间 `mode>=HANG && mode<=ROOF_ENTRY` 识别攀爬模式，但 `RELEASE=7` 落在该区间内。松手后每个客户端 tick 都会**重新播放 RELEASE 并把结束期限往后延**，结果永远不能执行淡出动画图层恢复原版动作。v0.11 用纯 Java `PeakAnimationPolicy.next()` 明确区分正在释放/攀爬/空中跳跃，释放只进入一次，9 tick 后撤销自身图层，恢复 Minecraft 自身待机、走路、奔跑。
2. 当本地玩家松开右键后，旧服务器攀爬 Pose 可能缓存十帧，导致临时显示幻影抓墙动作。v0.11 的 `PeakVisuals.pose()` 对本地控制玩家只读本地实际握持/跳跃状态，不复活陈旧的服务器 Pose；其他玩家仍由服务端同步，松开时发 inactive。
3. 蹬墙跳原本确有真实速度计算（法线外推 + 镜头方向 + 有界竖直分量）、7 tick 防吸回旧墙、冷却与自动重抓，但**缺少单独的空中动画**。原版切成挂墙结束或下落，视觉很生硬。现在墙跳保持无抓点的真正物理状态，但播放独立 10 tick 左右的双手推墙—收臂—腿蹬动作，Sable/多人客户端同步 `action=9`。重新抓到下一面墙立即切回抓墙动画；松右键即时结束飞行动作。
4. 之前屋顶“松手”套用墙面 `peak_release`，两臂姿势会瞬间从举过头到胸前，导致不好看。增加独立 `peak_ceiling_release`，双臂缓缓由高位自然下落，全部骨骼末帧回中立、释放后交还给原版动作。

## 动画重设计

- 11 套真实 Player Animator / Gecko JSON 动作；重新布置抓墙静止、向上交替手臂、侧移、顶棚双臂上举、顶棚横移/前爬、过渡、墙跳、墙面松手、屋顶松手。
- 手臂左右错开关键帧，降低头/腰摆动幅度，保留 Minecraft Steve/Alex 方块体形；屋顶腿只做小幅放松弯曲，身体始终垂直下坠。
- 同一循环动作的第 0 帧与末帧全部保持相同旋转与位移，避免每轮抽动；墙/顶松手动作在 0.45 秒末尾所有骨骼复原为原版中立姿态。
- 减小顶棚第一人称双臂向两侧额外平移量，以免双手离头部过远；松手/墙跳期间不再施加旧抓点的手臂偏移纠正。
- `scripts/check_peak_animations.py` 自动检验动画曲线时间、首尾循环、身体范围与释放末帧；`scripts/build.sh` 每次构建都要先通过检查。

## 验收与限制

- 普通 JUnit：释放只播一次、期限过后进入 NONE、顶棚使用独立 RELEASE、墙跳有独立动作且重新抓墙能中断它。
- Minecraft 普通 / Sable GameTest：原 14 项 + 新的「向新墙重抓」场景，检查按住 RMB 跳离墙后延迟结束可重新捕获新墙；此测试 **模拟玩家已移动到另一面墙**，并不证明完整空中轨迹一定到达目标。
- 客户端启动和 Player Animator 11 个片段真实解码检查。
- 仍待真人游戏录像评估 F5 身体、手掌贴墙和贴顶、释放时动作淡出与落地动作、不同 Sable 旋转速率/多人同步。不能把关键帧结构验证当成“动作已经好看”的实机验收。

控制不变：**按住鼠标右键抓握**，WASD 攀爬，**Space** 看向目标方向蹬墙跳，继续按 RMB 可抓住新的面，Shift 短冲跃，松右键放手。
