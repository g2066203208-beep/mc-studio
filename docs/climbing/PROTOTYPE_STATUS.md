# Sable Hands 0.2.0-alpha.1 开发记录 / 使用与验收

日期：2026-10-20（Asia/Shanghai）。**实验性源代码，绝非已通过实机测试的正式发布。**

## 运行环境

- Minecraft Java 1.21.1
- NeoForge 21.1.248
- Java 21（Gradle 云端构建使用 Temurin）
- Sable Companion 1.6.0：在 mod/build.gradle 中通过官方推荐的 Jar-in-Jar 声明；不要求把 Companion JAR 另复制一份到 mods 中。
- Sable 物理 Mod：建议采用与 MC 1.21.1 匹配的 Sable 2.0.x。**尚未确认玩家整合包中的实际版本；Sable 真实运动结构还未完成游戏内联动验收**。没有 Sable 时只提供普通世界方块表面抓握原型。

## 已落地源代码

- ClimbState：玩家侧隔离数据，左/右手独立锚点，切换模式与状态清理。
- GripAnchor：普通方块世界空间 / Sable 子世界结构 UUID + 本地触点及法线；每 tick 根据逻辑 pose 更新；原方块消失安全失效。
- SurfaceProbe：视线的完整方块表面射线，包含六个方向；Sable 使用 getAllIntersecting + inverse local ray + outline VoxelShape + 世界距离择近。
- ClientClimbControls：G 攀爬模式；左键左手、右键右手；取消原版攻击/使用输入；移动按键采样；窗口失焦或菜单关闭模式。
- ClimbNetwork、ClimbSnapshot：客户端仅传按键/移动意图，服务端重新计算抓握点，并返回校正快照。
- ClimbMotion：基于重力、接触面切线和单/双手最大长度的速度约束试验；不直接传送玩家或关闭重力。超远锚点和过快结构跳跃释放。
- GripRules、GripRulesTest：独立 Java 逻辑、JUnit 5 自动化测试，覆盖意图重放/非法数值/单向绳长约束/极端结构跳跃/速度边界。

重要：项目没有新增骨骼动画或角色贴图，玩家仍使用原版第一人称手臂和皮肤；当前也没有真正的第一人称握拳或左右手贴紧方块的可视化动作同步。

## 控制（预设）

- G：开启/退出攀爬模式。
- 在攀爬模式：鼠标左键按下/保持左手，右键按下/保持右手；分别松开就释放。
- 视线：选择抓握方块表面；推荐先试约 2.75 方块内的石墙、天花板、平地。当前并非鼠标游标逐手 IK 定位。
- WASD：在抓住至少一只手时尝试沿当前表面的切线移动；没有抓住不能空中飞行。
- Esc、打开物品栏、失焦、死亡、切换维度：清理抓握或退出模式。

## GitHub 云端构建

在仓库 .github/workflows/build.yml 上自动执行：
- checkout
- Java 21
- bash scripts/build.sh (Gradle build)
- 上传 JAR；在有单元测试结果时上传 test-results/test/*.xml 的 XML 证据

不要把每个 push 产生的早期失败/取消工作流误读为最新源码失败。使用 PR #3 head SHA 对应的最近一次成功运行作为有效记录，并核对版本号。
当前验证条款必须据实逐个标记，不准从编译结果推断玩法实测。

## 手工验收案例（未执行）

1. 独立 NeoForge 1.21.1 测试实例（不使用正式存档）安装该 alpha JAR + 匹配的 Sable 物理 Mod。
2. 在新建测试世界用石方块建高墙、顶棚、地面。G 开启攀爬；先只按住一手，观察是否悬挂并受重力拉住；松开应下落。
3. 在墙上先左手抓住，再转视线把右手抓向另一个地方，松开左手，观察右手是否独立承力。
4. 从天花板下方向上看，按左/右键是否抓到底面而非“只支持墙壁”；两手松开自然下落。
5. 从地板俯视抓上表面，WASD 是否沿地面移动且不悬浮。
6. Sable 内建立静止、缓慢平移、倾斜旋转方块平台，依次检查按住一手/双手的追踪、松手速度与无穿模。
7. 断线、进入 GUI、失焦、死亡、传送、两人专服，均需正常状态清理。

## 当前未通过证据的功能

- 真实开发客户端启动与进世界、原版手臂显示正确性；
- 真实 Sable 2.0.x 动态船体上的命中/追踪与碰撞；
- 多人专用服务器精确同步、弹簧速度/玩家飞行反作弊限制；
- 任意复杂方块形状（非固体 outline 有可能可抓，但空气/无形状方块不抓）；
- 稳定的从墙壁转角过渡、身体贴地匍匐、真实双向力学约束、体力/疲劳、手脚动画。

以上都属于后续 M1~M4 持续开发验证，不得当作已完工；尤其现阶段不可直接覆盖用户正式 mods 或存档。

## 技术风险与下一任务

1. 目前速度级控制器是 alpha 算法，不是 Rapier 刚体玩家；Sable 已有 Entity Tracking 时可能与动态锚点继承速度重复，需在真实运动结构中观察后去重。
2. 使用 BlockState.getShape / ClipContext.Block.OUTLINE，实现了任何**非空气、存在可拾取轮廓**的方块都可能抓握的玩法；非实体装饰物被允许是产品选择，其作为锚点的承重游戏平衡尚待测试。
3. 客户端使用本地预测 + 服务端收到意图后发权威锚点快照，但尚未实现柔和插值校正；联机高 ping 可能抖动。
4. 最大距离、力、速度和摩擦均为实验参数，需通过实际攀爬测试调校，不能据此称为 White Knuckle 级手感。
5. M1 下一任务：在图形客户端进入游戏，录制基础墙/天花板/地板操作，纠正动作与相机问题。M2：真实 Sable 飞船场景加速、旋转、释放实测，修复漂移和穿墙。M3：双人专服。M4：整合包组合测试。
