# Sable Hands｜玩法与工程规格 v0.1

日期：2026-10-20。状态：已规划、未实现。唯一目标：Minecraft 1.21.1 / NeoForge 21.1.248 / Java 21；当前工作室沿用原有构建骨架。参考 White Knuckle 双手攀爬交互；依赖的 Sable 指的是 RyanHCode 的 Minecraft 物理 Mod，而不是同名开放世界游戏。

## 1. 产品目标与非目标

- 第一人称、双手独立抓握、可自由悬挂/爬墙/贴地拉行/天花板横移。任意有有效碰撞或可配置抓握几何的方块，不因种类、材质或法线方向被任意禁用。
- 支持静态普通世界方块，以及 Sable Sub-level 中移动、旋转、倾斜的方块；抓点相对所属结构不漂移。
- 默认保留 Minecraft 原版第一人称方块手臂/皮肤，不增加复杂角色模型、Spine、IK 骨骼插件或专门美术包；只通过原版手臂的简单位移、旋转、挥动、握紧姿态反馈动作。技术优先于视觉。
- 初版不要求给飞船反向施加玩家拉力、不引入完整布娃娃或刚体人体；首先建立可验证的玩家运动约束，之后再评估 Rapier 联动接口。
- 不增加物品、工具、专用攀爬方块，不将玩法绑定特定装备。体力/手部负载作为可配置后续功能。
- 与原版正常走路、挖掘、战斗、摆放、使用物品共存；不可永久占用左右键。

## 2. 交互和状态

按键草案（最终可在控制设置修改）：
- G：切换攀爬模式（也可配置按住启用）；HUD 显示当前模式并提供退出提示。GUI、聊天、失焦、死亡、切维度时自动退出并释放抓点。
- 攀爬模式内：左键按下/保持控制左手，右键按下/保持控制右手；松开各自按键就释放各自锚点。必须正确处理快速切换、重复触发、失焦释放。
- 鼠标视角保持原版，用视线中心与左/右手偏移的方向共同寻找抓点；允许调整独立手偏移/抓取角。
- WASD：有至少一只手抓牢时施加受限制的身体牵引，行为按接触面和镜头方向投影，保证玩家可以横移/上移/下移/贴地拉行/天花板移动。WASD 不得在没抓点时赋予飞行。
- Space：可配置为借力蹬跳、松手跃出，不可由持续按键制造无限上升；Shift：缓慢下移/精细控制。
- 攀爬模式外所有原版行为不变。物品使用、攻击、破坏、放置必须在攀爬模式下明确抑制，而不是全局修改原版管线。

每只手分别具备 FREE、REACHING、GRABBED、RELEASING、INVALID 状态；玩家具备 GROUNDED、ONE_HAND、TWO_HAND、AIRBORNE、TRANSITION 状态。左右手必须有独立持久的数据与网络序号，不可共用一个全局抓点。

## 3. 任意方向与方块形状

攀附目标是方块的几何表面而非仅方块的四个侧面：
- 墙面：法线水平，允许纵向和横向移动。
- 天花板：法线朝下，允许悬吊及沿切线平移；重力持续作用，必须有抓点才悬挂。
- 平地：法线朝上，允许贴地/匍匐状态手抓并沿表面拉动；玩家不能因抓住地面而离地悬浮。
- 斜坡、旋转船体、方块转角：在任意世界法线方向投影/约束；两手可位于不同但相邻的平面甚至不同结构，需处理约束冲突并安全松手。
- 完整方块、玻璃、石砖、木板、树叶、楼梯、半砖、台阶、栅栏、墙、活板门、绊线钩类小形状等：首先采用真实 VoxelShape 碰撞/轮廓，不使用静态“可抓方块”材质白名单。
- 空气、流体及无实体形状方块（花、火、草等）不可默认承重；提供专门抓握形状/标签覆盖配置。形状为零时不能凭空生成稳定锚点。
- 需设置最小可承力接触面积、最大伸手距离、线-of-sight 检查和防穿墙规则；细小形状的参数与完整方块分开，默认尽量宽容但不能从方块背面隔墙抓。

建议第一版抓取距离为可配置约 1.5–2.5 方块的候选范围，实际最大可达距离与人体碰撞和原版交互范围独立校验；这只是设计参数，未调试，禁止假称已选定最佳数值。

## 4. 动态 Sub-level 抓握

锚点数据结构（逻辑字段）：
- gripId、handSide、dimensionId、surfaceKind（STATIC / SABLE）、structureUuid（仅动态）、blockPos、localContact、localNormal、poseRevision、createdTick、lastValidatedTick、valid。
- 静态锚点：世界坐标和方块形状面信息。
- Sable 锚点：以结构自身的局部坐标保存接触点与法线。不得只保存世界坐标；每逻辑 tick 按该结构 logicalPose 转回全局，客户端用 renderPose 平滑显示；法线须用方向变换而非位置变换。
- 找到附近候选 Sub-level，用结构当前及上一 tick 姿态进行 broad-phase，再对其局部 VoxelShape 做窄相位/射线求交；不能将旋转局部 AABB 粗判结果当精确抓点。
- 结构 UUID 失效、区块卸载、碰撞形状改变、原方块被挖掉或结构消失：单手独立释放，重新算惯性并回到合法运动状态；客户端不能因为丢帧创建隐形桥。
- 对急速平移、旋转和低 TPS 使用连续/扫掠检测，限制单 tick 的纠偏量，避免穿方块和瞬移。旋转动态结构上不同距离的抓点线速度不同，释放时应继承锚点处线速度与合理玩家相对速度。
- 先只修改玩家运动，不向飞船施加物理反作用力；需评估 Sable API 的约束支持、线程时序、仿真步长与同步能力后才考虑该功能。
- 采用 Sable Companion 1.6.0 API 作为推荐入口；与完整 Sable 的行为用隔离适配层封装，不直接复制上游内部源码。Sable 尚未被证实存在可直接使用的“玩家手抓住刚体”通用 API。

## 5. 物理求解原则

实现一个运动控制器而非 setNoGravity(true) + 强制 teleport：
- 对玩家重力、速度和碰撞做统一积分：按抓握锚点计算运动目标/允许的最大手臂长度，投影方向上的推拉输入，求解玩家身体的速度/合法位置，使用世界与动态结构碰撞再约束位置。
- ONE_HAND：玩家被单一锚点约束，可下摆、左右摆动，松手按瞬时速度落下。
- TWO_HAND：两锚点共同约束，不允许无限位移；过约束和两结构互相分离时采取明确优先级，优先释放最近失效的手，避免爆炸速度。
- GROUNDED/FLOOR_GRIP：玩家遵守地面碰撞和摩擦，不因抓地而上浮；允许向前后拉动、贴地滑行和匍匐。
- CEILING：身体在表面下方，禁止穿过实体方块；双方都释放后正常下落。
- 接触其他方块时不可穿模；有限步长解决快速坠落抓住墙面的穿墙问题。
- 原版玩家不是天然的 Rapier 动态刚体；第一阶段的“真实”定义是确定的抓点约束、惯性、碰撞、重力及服务器校验，不虚称完整刚体模拟。

## 6. 原版手臂显示

- 不制造新手臂贴图或第三方骨骼。优先从已有 Hand/ItemInHand 渲染管线轻量调节平移/旋转，使左/右方块手臂跟随状态摆出抓握姿势。
- 保持玩家原皮肤，提供禁用手臂特效的设置；镜头移动/双手切换无闪烁，视角不剧烈抖动。
- 第三人称先维持原版安全姿态，不以新建复杂动画模型作为 MVP 的先决条件。
- 注意手持物占用，攀爬模式默认隐藏/压低当前物品的第一人称动作但绝不凭空删除玩家物品。

## 7. 客户端/服务端同步

- 服务端权威：客户端只传左右手按键意图/序号、视线和预测输入；服务端查形状、距离、遮挡、维度、Sub-level、碰撞与体力规则，回传权威锚点与状态。
- 客户端预测 + 温和校正，避免每 tick 原地回弹；防伪抓点、防超出有效距离、防利用快速按键飞行。
- 不要用静态全局 Map 永久缓存玩家，离线、退出世界、死亡、切维度需清理。
- 设计专门的开发日志：手状态、锚点 ID、局部/世界位置、服务器 tick、误差、纠正次数，默认关，开发命令开。
- 单机集成服务端与专用服务器行为分别验证；断线重连不会永久悬空。

## 8. 建议模块与开发顺序

待实现的架构：
- input/ClimbInput：键位/鼠标采样、模式开关、失焦处理；
- grip/GripState + GripAnchor：左右手状态与锚点；
- surface/SurfaceProbe：静态 VoxelShape、旋转结构形状探测和命中法线；
- sable/SableStructureAdapter：UUID、局部/世界转换、逻辑/渲染姿态、结构速度；
- movement/ClimbController：重力、手臂长度、碰撞约束、单/双手、地面/天花板；
- network/ClimbPayload：服务端权威、序号、客户端预测和校正；
- client/VanillaHandPose：原版手臂姿态；
- debug/ClimbDebug：可开关的可视化和测试指标。

里程碑：
- M0：调通 Sable + NeoForge 依赖、表面探针，独立验证所有 6 个面与多种 VoxelShape；无玩家运动。
- M1：静止墙、地板、天花板真实双手抓握、受限移动、合法松手；原版手臂简易动画；无 Sable 船体。
- M2：移动/旋转 Sable 结构，锚点局部化与速度继承，抖动/穿模回归；先验证慢速后验证高速。
- M3：复杂形状、转角、抓点位于不同结构、精细手感/体力和服务器同步。
- M4：整合包（特别是 Create、Aeronautics、TFC）组合测试、性能采样、错误恢复和发布。

## 9. 不可妥协的验收

- 静止墙面任意高度可抓、不能穿墙、松开双手就落下；仅松一只手仍被另一只约束。
- 天花板从下表面抓住并横移，不能穿过天花板；完全松手后自然坠落。
- 平地可抓握，贴地移动，既不悬浮也不自动变成攀岩梯子。
- 楼梯/半砖/栅栏/树叶/玻璃与 Sable 旋转方块用统一表面规则，特殊例外写入测试记录。
- 静止、匀速、加速、旋转、急停、结构销毁、区块卸载分别测试，并记录抓点漂移、位置突变、平均/峰值校正。
- 全程无客户端崩溃、服务端崩溃、重复物品操作、方块误破坏、无限攀升漏洞。
- 在同一网络条件下做单机及双人 dedicated server 演示；编译成功不等于游戏内验收。
- 所有开源依赖须记录来源分支、commit、许可证；不要提交第三方 JAR 或其源代码。

## 10. 决策记录

已决定：优先功能、原版第一人称方块手臂、全方向抓握、平地/天花板/墙面、Sable 动态结构、Java 21/NeoForge 1.21.1。

尚待测试选定：攀爬模式默认切换键、抓取距离、手体约束长度、推进速度、碰撞及体力数值、Sable 2.0.6 与既有实例组合兼容性。这些必须用测试结果而非臆测确定。


## 11. 2026-10-20 更新：双手交互 V2（优先级高于旧版输入章节）

用户实际试玩 0.2.0-alpha.1 后确认：不再要求默认 G 切换模式，空手面对有效抓点时**右键点一次锁定右手，左键点一次锁定左手；再点一次松开**，不是长按；未来可配置为长按式。保留原版手臂，但第一人称必须真正伸向接触点，第三人称必须有左/右手独立动作，并通过网络让他人可见。

新增硬性目标：右手抓墙悬挂时，左手可取出手枪（建议可重绑定 X），左键射击、R 换弹且不影响右手锚点；有物品的手优先交给物品动作，空手时才判断抓墙。原版放置、破坏、使用物品不得被全局抢占，地面抓握需要明确的蹲下/修饰键意图规则。

**正式细则见 [HAND_INTERACTION_V2.md](HAND_INTERACTION_V2.md)**，其输入路由和动画要求覆盖本文件前面有关“按 G / 必须长按 / 仅简单手臂偏移”的旧草案；物理、Sable、几何和联机验收要求继续有效。V2 尚未实现，不可沿用旧 alpha 的成功 CI 宣称已通过。
