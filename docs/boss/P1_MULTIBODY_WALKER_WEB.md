## 真正的物理机构

- 1 个有质量、有惯性且自由漂移的主机身 + 6 根上腿 + 6 根下腿：共 13 个独立 Rapier 动态刚体。
- 6 个髋关节 + 6 个膝关节：共 12 个 Rapier Revolute 真正的旋转约束，分别有限位，碰撞、质量、重力与地面接触由 WebAssembly 处理。
- 腿的真实尺寸：上节长 1.65 格、下节长 1.75 格。中心机身宽约 5.6 格，长约 5.3 格，六只独立金属脚各有真实方块碰撞体。
- 真实电机：按当前角度和目标角度计算 PD 伺服器转矩；对铰链两侧动态刚体施加等大反向角冲量，电机有硬转矩上限。没有直接设置 RigidBody 世界坐标或修改动画姿态冒充受力。
- 控制：站立、两组三足交替抬腿、前进步态实验、断电（真实失去电机保持力），撞击、断腿。拆一腿时真实解除 2 个关节约束，四脚一体式假腿已经被废弃。
- 动力：Create 风格马达 RPM 影响步态相位；浏览器齿轮箱选 1:1 / 2:1 / 4:1，近似 90% 效率，降低输出 RPM、增大允许的实际伺服转矩。不是原版 Create 全部 SU 网络。

## P1.1 — 把齿轮从外观变成真正的控制输入（2026-10-22）

修复了原来“Create 齿轮模型在动，但实际的 Rapier 关节总能凭空获得动力”的设计缺陷。

- **26 个整数坐标上的独立 Create / Simulated 方块**组成可验证的动力网络；源头是 `create:creative_motor` 位于 (0,0,5)、面向 north，经过 Z 轴主干上的 3 个 `create:large_cogwheel`、4 个 `create:shaft` 等，再由 6 组垂直大齿轮转向、6 个 `create:clutch` 和 6 个 `simulated:swivel_bearing` 接收端驱动髋关节。三排支路 z=-3,0,3，避免错误的额外啮合冲突；左右齿轮实际有相反 RPM 符号。
- 使用 `strict-core.mjs` 的 Create 1.21.1 源码规则求解 **轴向、Facing、离合器 POWERED 状态和啮合旋向**。一个未连通的支路不会继续“自动传送动力”。
- 每次控制器步进前读取实时传动图。**关掉主马达后 12 个物理关节都不会再得到主动驱动转矩；断开 L1 离合器后，L1 髋/膝关节驱动转矩=0，另外 5 腿仍然可以获得动力**。供能状态不是只更新文字：真实的 Rapier `applyTorqueImpulse` 条件由这个网络控制。
- 模型由一个个 1×1×1 的独立方块组装，齿轮、轴、马达和轴承的视觉块按同一套整数方块坐标创建，不再用 5×7 格宽的拉伸纹理大盒子冒充一整排方块；联网后自动使用原版 JAR 中可解析的真实静态 JSON/PNG 资源。
- 面板可逐个看到 6 条支路的实际输出 RPM、已接通支路、传动连接数、主马达和离合器状态。可以直接按键断开/接通动力，观察脚的失力、机身姿态与重力反应。
- `viewer/rpms/tests/boss-powertrain.test.mjs` 对 26 个整数 BlockPos、相互垂直大齿轮啮合、六个接收端、离合器单独断开、RPM 方向与齿比参数进行断言；真实 Chrome 还点击页面按钮并检查 `legAngles[].deliveredTorque`，不准用齿轮动画替代物理出力。

**当前仍未等同完整 MC 原版：** Create 的 `RotationPropagator` 仅有已核查的基本连接类型；从传动支路到小腿的跨运动关节供能/旋转耦合仍然使用浏览器物理伺服器简化模型；齿比选项和 8 SU/RPM 轴承假定负载尚非原版 Simulated 验证数值；变速器/扭矩限制/空气动力/复杂机械加工/生成建造蓝图尚需进一步开发。P1.1 属于“传动连通能够真实控制多刚体机器人”的阶段，不是 1:1 完整航空学移植。
