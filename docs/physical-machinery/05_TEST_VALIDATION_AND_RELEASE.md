# RPMS-VV｜验证、试验台与阶段放行方案 v0.1

基线原则：需求每条有 ID、方法、测试环境和证据位置；任一 GATE 不满足则不得进入下一量产/玩法阶段。形式参考 NASA 需求验证矩阵，但本项目并不声称是航空认证项目。

## 1. 从静态设计到真实游戏的 V 模型

1. 需求（SYS-nnn） ↔ 验收测试用例（TC-nnn）；自顶向下分解、自底向上集成。
2. 控制纯算法 ↔ 单元测试：数学、运动学、角度限位、支持区、故障状态机。
3. 关节适配器 ↔ Sable/航空学 API 集成：原生轴承、约束、物理单位、摩擦和马达响应。
4. 原型分段拼装 ↔ GameTest：实际多段 SubLevel 连接与驱动，不是一次性传送。
5. 机器人全身 ↔ 游戏内试验台：去掉支撑架后站、走、转、跌落、受损和重启。
6. Boss 应用 ↔ 玩家试玩：持续攀爬、碰撞伤害、破坏部件与关节、AI 协调、视觉和性能。

## 2. 核心关卡 Gate 与拒绝条件

| Gate | 试验工况（与编号） | 通过门槛（先为候选，实测后冻结） | 一票否决 |
|---|---|---|---|
| G0 环境 | TC-001: MC1.21.1/NeoForge21.1.248/Java21/Aero/Sable 单独与组合加载 | server+client 正常启动，准确 SHA/版本/依赖锁定 | 冲突/类缺失/mixin 异常 |
| G1 基础关节 | TC-010: 两段各有 UUID，1 个真 Sable rotary constraint; TC-011: 正负角度与堵转; TC-012: 无动力与超限 | 实测相对角度、阻尼/扭矩饱和，不卡死、不瞬移 | setPose 假运动、自连接、过载传送 |
| G2 单腿机构 | TC-020: 3 DOF真实装配; TC-021: 逐轴标定; TC-022: 100 次抬脚/落脚; TC-023: 受载/失电 | 外部**可见**夹具支持，3个关节指令均可物理执行；无脚板穿地或无故飞出 | 夹具冒充独立站立、限位失效 |
| G3 四足站立 | TC-030: 13 刚体/12关节；TC-031: 30秒站立; TC-032: 断一足; TC-033: E-Stop | 移除外部夹具后真正站立 30 秒，真实足接触与 COM 支撑稳定；关机可真实倒下 | 使用 noGravity/隐藏推进器、无安全断电 |
| G4 低速行走 | TC-040: 20格直线; TC-041: 停机; TC-042: 90°转弯; TC-043: 上下半格/一格台阶 | 确认步态/IK/接触反馈驱动；直线≥20格，5秒内停止漂移<0.5格候选目标，20TPS 基线 | 强制 Pose、关节穿模、无关节反馈 |
| G5 耐久/损坏 | TC-050: 单条腿严重损坏; TC-051: 节点被拆; TC-052: 换 UUID; TC-053: 重载存档 | 正确限力/跛行或真实跌倒，不能加载其他船；重启不重新开满扭矩 | 误控制别人的 SubLevel、物资复制 |
| G6 Boss 与 PEAK | TC-060: 运动刚体攀爬; TC-061: 跨关节; TC-062: 尾扫撞击; TC-063: 部位健康 | 物理碰撞和结构变化确实反映在战斗能力和 UI，双人可重复 | 假 collider/假血条、抓握鬼影 |

G4 台阶和坡地属于后续扩展时可拆成 G4a/G4b，若 G4 核心平地达不到，不得强行标“通过”而省略台阶测试。

## 3. 实时测量和可重现实验包

每条记录至少包含：
- commit SHA, Gradle/JDK, NeoForge, Create, Aero, Sable 及所有选配 add-on 文件版本与 hash。
- test ID、world seed、机器装配方案 revision、总块数/各刚体 UUID/质量、关节限幅、供能参数与控制参数。
- 真实 tick、物理 step frequency、服务器 MSPT(avg/P95/P99)、physics step(ms)、joint actual/target、saturation count、足接触连续性、COM 支撑裕度和故障 ID。
- 预期与观察、失败调用栈、失败前后 debug log、必要录像，以及独立临时世界复现说明。
- 不从 FPS 反推服务器 TPS，不从关节 UI 目标角推断 actual angle。
- 联机验收需 1 人与 2 人分别记录；存档重载单独验证，不使用已经被 GameTest 破坏的正式玩家存档。

## 4. 自动 CI 流水线

A. **Design lint（本阶段可跑）**：机械图拓扑、唯一 joint/part IDs、12 DOF、13 segments、动力/传感器 BOM、角度范围、风险测试引用。生成校验结果，不加载 MC。
B. **Unit tests（研发阶段）**：FK/IK、关节 shortest angle、PD 饱和、支撑多边形、足部状态机、序列号超时/失联、伤害重新规划。
C. **Real Sable GameTest（G1/G2）**：在 NeoForge 21.1.248 的临时世界启动相同 pinned 二进制版本，原生装配、关节真实 tick、不同 UUID、动力丢失、实际角运动、碰撞记录。
D. **Full Aeronautics GameTest（G3/G4）**：13 个 SubLevel 真实站立与行走、数据抽样、多人基本稳定性，必须有录制。
E. **Client smoke / player visual**：图形客户端进世界、PEAK 抓点、机体外观/关节装配位置，人工视角录制。
F. **Load/regression（G5/G6）**：连跑、故障注入、结构破坏、联机、Sable拆分、重启、性能压力。

禁止只上传设计 lint 的绿色 badge 就声称跑过 Sable 真实行走。

## 5. 放行票据与缺陷分类

每次 release PR 附：
- SRR/PDR/CDR/TRR/Gate 类别与负责人审批。
- 需求→测试矩阵的 Passed/Failed/NotRun/Blocked 明确分栏；每条 test 证据超链接。
- 安全 P0 缺陷均为 release-blocker：UUID 串船、无限扭矩跑飞、无责任取消、复制库存、服务端崩溃/存档污染。
- P1 缺陷可延期必须附变更和补救计划，不能把“后续优化”无限拖延。
- 玩家体验美术可以独立反馈，但**关节真实、物理稳定、失电倒地**是不可豁免的核心验收。
