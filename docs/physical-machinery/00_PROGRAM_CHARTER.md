# RPMS-000｜物理机械运动平台工程章程
**版本** v0.1-draft（系统需求评审 SRR 前）；**状态** 设计基线候选／不是已运行的机器。
**项目** REME Physical Machinery System（RPMS）。**主管** 工程项目负责人（ChatGPT 执行与统筹）；**产品验收权** 用户。
**运行基线** MC 1.21.1、NeoForge 21.1.248、Java 21、Sable 2.0.6；Aeronautics/Simulated 与可选组件版本仍待锁定并通过联机启动验证。

## 1. 产品宗旨 / ConOps

用户在 Minecraft 中用真实方块造出机械物体，组装为 Sable 物理刚体，安装关节/动力/传感器/控制方块后能进行真实的闭环运动。运动来自 Sable 的重力、碰撞、摩擦、惯量与受限电机，绝不是按动画路径传送结构；每个可转动部件都是实际被组装且可独立损坏的刚体段。
首个验收产品为一套可复用的**单腿—四足步行器**，随后将同一平台用于巨型可攀爬 Boss。其他未来产品可以是吊机、机械臂、步行载具、机械动物，不将 Boss 行为逻辑写死在通用机械控制层。

### 允许的操作模式
- **手动建造**：玩家从零拼装，主动组装/拆卸，连接轴承、动力和传感器。
- **工程调试**：控制台查看刚体树、关节角、马达扭矩、重心、地面接触、故障与性能；测试人员可以独立启停驱动。
- **遥控/指令**：玩家通过控制器指定前进/转向/站立，运动算法算如何实现，不修改刚体 Pose。
- **自主行为**：导航/感知输出期望身体速度，再由步态、平衡、关节执行；Boss AI 只是上层一种指令源。
- **损坏/修复**：缺失部件影响质量、受力和功能；可选蓝图修复/再生根据安全策略执行，不可任意复制物品。
- **安全关机**：失电、低 TPS、传感器无效、关节过载时进入物理安全的降级或受控倒地。

### 绝对禁止
1. 每 tick 强制 setPose/teleport 身体来冒充步态；只允许出生、放置、离散救援在显式规则下传送。
2. 在承重测试时悄悄开启 noGravity、不可见支撑实体、隐藏无限力；也不能把装饰动画当真实接触。
3. 没有接触信息却宣称精确足压；没有扭矩/速度读数却宣称已测出最大承载能力。
4. 新增方块刷新 Boss HP、自由复制库存/机器 NBT、跨 Sable UUID 误改玩家飞船。
5. 只见编译成功就标记“可走路”；视觉录制/物理 GameTest/压力测试必须单独举证。

## 3. 工程生命周期门禁

- **SRR｜需求评审**：功能、约束、用例、唯一需求 ID、验收方法齐全；发现不可能的要求要登记变更。
- **PDR｜初步设计评审**：零件树、轴向定义、传动比、力矩预算计算方法、传感器/命令 ICD、稳定性算法和最大风险清晰。
- **CDR｜详细设计评审**：核心物理版本锁定，设计参数/范围/单元测试、GameTest 测试台图样与失败安全路径齐备。
- **TRR｜测试准备评审**：临时世界、日志仪表、回滚、自动化触发和测试记录可重复。
- **SIT｜系统集成**：单关节→一腿→四腿按门禁通过，同步多人、存档和异常。
- **UAT｜用户验收**：实机录像/亲自操作能站、走、转、损坏、停止，无伪装力/运动。
每个门禁输出：版本 SHA、测试环境 mod hashes、测量数据、遗留缺陷、负责人结论。没有门禁签字，不标记下一阶段 Completed。

## 5. 范围、限制与决策

- 首版设计的是**通用机械运动平台 + 真正四足行走的 MVP**，不是完整 Boss 战，也不是现实硬件制造交付。借鉴真实机器人系统工程方法，但在游戏物理时基、尺度和 API 内进行验证。
- 第一架机器先做「独立两轴承测试台」和「一条有外部固定机架的腿」；单腿不可能自行四足站立，必须标明机架提供测试支撑。
- 四足机 4 × 3 = 12 个**主动驱动自由度**（髋侧摆/髋俯仰/膝俯仰），脚踝在首版用**被动限位/弹性足垫**降低刚体数量。选择是工程优化，不等于真实动物没有踝关节；未来增加四个主动踝自由度之前要通过性能门禁。
- 初代风格允许机械恐龙，重心、力学和运动必须真实；复杂头颈/尾/爪属 Boss 扩展阶段。
- 所有尺寸、质量、最大扭矩、角度和控制频率在 PDR 前均是*候选值*；不得拿现实 N·m 假装 Sable 使用 SI 单位。需先做尺度/摩擦/惯量识别实验。

## 7. 决策记录

| ADR | 决定 | 状态 | 原因 |
|---|---|---|---|
| ADR-001 | Sable 作为唯一权威刚体物理求解 | 提议 | 避免第二套竞争物理状态 |
| ADR-002 | 12 个主动关节，首版踝关节被动 | 提议 | 降低约束数、先验证基本步态 |
| ADR-003 | JointAdapter 隔离 Aeronautics 与将来自研马达 | 提议 | 版本/控制模式风险 |
| ADR-004 | 采用先静态爬行步态、后动态小跑 | 提议 | 更易验证支撑和足部接触 |
| ADR-005 | 平衡失败时真实跌倒，不提供魔法稳定 | 提议 | 用户明确要求真实拼装运动 |
| ADR-006 | 结构蓝图是部位健康基准，不是任意 HUD HP | 提议 | 损坏与真实机械功能一致 |
