# RPMS-MECH｜机械总体设计、装配与零件定义（PDR 候选）
此文件是机械运动平台的工艺定义，不是纯装饰模型。物理装配/尺寸/惯量尚未实物标定。

## A. 结构体层级（首架 RPMS-Q12 四足机器）

以 +Z 向前、+X 为右、+Y 向上。躯干 11×5×4 格、机架高度约 6 格、上腿 3 格/小腿 3 格均为设计样机候选，装配后的腿跨度与重心由物理测试最终确认。

~~~text
Machine RPMS-Q12
  ROOT BODY (刚体 UUID0) : 机架、动力传动、Brain、传感器、维修/数据端口
  ├── LEFT_FRONT (LF)
  │   ├── J-LF-HAA [axis +Z] -> HIP_CARRIER_LF (刚体 UUID1)
  │   ├── J-LF-HFE [axis +X] -> UPPER_LF       (刚体 UUID2)
  │   └── J-LF-KFE [axis +X] -> LOWER_FOOT_LF (刚体 UUID3; 足垫固定其上)
  ├── RIGHT_FRONT (RF) : 同样 3 段、3 关节
  ├── LEFT_REAR   (LR) : 同样 3 段、3 关节
  └── RIGHT_REAR  (RR) : 同样 3 段、3 关节
~~~

物理小计：ROOT 1 + 4×(HIP_CARRIER/UPPER/LOWER_FOOT) = **13 个 Sable 刚体段，12 个主动旋转约束**。这里的 HAA（髋外展内收）指绕身体局部 Z 轴的髋侧摆；HFE（髋前后俯仰）和 KFE（膝屈伸）是局部 X 轴旋转。上述轴在真实安装位置需经校准并允许镜像腿的 sign 参数。脚掌/足垫首版固定于 LOWER，属于真实接触面但不增加独立主动踝自由度。

为什么不能说「四条腿各一段」？只有拥有分段 Sable UUID 和物理 joint handle 才会真实改变关节角和载荷；若涂胶跨过某个关节，这一对段会被组装成一个刚体，关节就无法运动。

## B. 机械功能分区与实体布置

| 区域 | 内含可拼装机械零件 | 理由 | 受损后真实反馈 |
|---|---|---|---|
| ROOT-CENTER | 低位动力核心、重物块、电机分配器、主控制器 | 降低重心和扭转惯量 | 动力下降/断电 |
| ROOT-FRONT | 前髋底座两侧对称、前传感器架、激光/光学测距 | 前进落脚和障碍判断 | 前腿无法抬脚/盲区 |
| ROOT-REAR | 后髋底座、机械连接板、尾部连接接口（扩展） | 抗后倾、转向稳定 | 跛行/转向响应下降 |
| FOUR HIP CARRIERS | HAA 底座 → HFE 底座的正交轴转换 | 让两个主动轴真实串联而不是假“万向模型” | 一侧侧摆失效 |
| UPPER LEGS | 承载骨梁/装配胶、端板和限位块 | 传递重力与扭矩 | 质心变化、杆件断裂 |
| LOWER_LEGS+FEET | 膝关节从动板、下腿骨架、固定足垫、接触传感器 | 地面反力、摩擦、碰撞 | 脚掌打滑/不触地 |
| BACK SERVICE BUS | 机械轴/仪表诊断、紧急停机、线路检查 | 可在身体外部检查与拆修 | 无调试能力/停止许可 |
| ARMOR/ORGANS（Boss 扩展） | 真实可敲掉的装甲与器官方块 | PEAK 可攀爬、结构减损 | 功能退化、失衡或死亡 |

首版足底接触由 Sable VoxelShape 的真实碰撞处理；如果可用 API 不能给出接触冲量，则必须用标注 ESTIMATED 的短程探针与脚掌近地速度估计状态，不得宣称「真实压力传感器已完成」。专用 FootContactPad 方块开发后替换。

## C. 原型机械 BOM 估算（准确数量须经组装图与真实载荷测试复核）

- Sable/航空学物理组装器：装配工艺工具，不一定一台机器要永久内置 13 个。
- 刚体段：13 组原版方块、粘合、碰撞、结构强度与质量材料。每段单独组合。
- 关节：12×单自由度 Rotary Servo，或经许可/版本验证的 Aero Swivel/Servo Bearing；每关节需要 2 端实体连接，UUID 不可相同。
- 动力：1×中央动力系统、若干机械轴/传动/转速转换、分配器、可选离合/刹车，每关节一个驱动通道与 power budget；实际用多少方块根据 Create 传动路线确定。
- 身体反馈：1×姿态传感器，1×速度传感器；4×足部触地感应，关节角状态每轴 1 份（可以由适配层从 Sable pair pose 算，不一定多摆 12 个实物编码器方块）。
- 控制：1×核心/行为大脑、1×平衡控制器（可集成在核心）、1×安全监督、12×电机适配通道（可以是一块可配置多通道方块，而非强制放 12 个）。
- 可选：4×前方/落脚测距光学探针、1×E-stop 操作面板、1×工作记录器。
- 带身 Boss 扩展：装甲、脊背攀附点、器官、咬击/尾部冲击传感器、Boss 身体蓝图；不算基本步行器 BOM。

可机读初始采购/开发矩阵：COMPONENT_REGISTER.csv。Ready = 可用已核对源码；Probe = 版本/承载能力待实机验证；New = 必须开发。把 Ready 理解为“已经让恐龙走路成功”属于错误。

## D. 机械设计参数与计算规则

### D1. 重力载荷与关节额定扭矩

必须先测 Sable 的有效质量 M、重力加速度 g_eff、杆长 L、各段转动惯量 J、摩擦与最大接触力。静态某一承重腿的支撑反力由接触分配计算，单轴近似：
  tau_load ≈ |(p_contact - p_joint) × F_contact| 在关节轴的投影
  tau_design >= safety_factor × max_measured_or_computed_load

建议初始安全系数候选 1.5–2.0，未做引擎等效单位标定不能把结果标成现实 N·m。动态加速还要加入 J*alpha、重力补偿、摩擦和碰撞冲量。PD 输出：
  tau_cmd = clamp(kp*angle_error + kd*angular_velocity_error + tau_feedforward, -tau_max, +tau_max)
并约束角速度、角加速度和能耗。存在过载时角度不一定跟得上目标，这是应该保留的真实物理表现。

### D2. 关节范围（全部是原型候选）

| Joint | 自由度 | 初始允许范围（degree） | 约束用途 |
|---|---|---|---|
| HAA | 髋外展/内收绕 +Z | -25 到 +25 | 侧向放稳支撑面积 |
| HFE | 髋俯仰绕 +X | -50 到 +60 | 前后迈腿 |
| KFE | 膝俯仰绕 +X | 10 到 135 | 收腿/伸腿；镜像腿 sign 校准 |
| Foot | 与下腿一体 | 无主动自由度 | 固定摩擦鞋底 + 被动弹性接触 |

**这些角度不是航空学现成轴承的保证能力**，是初步运动工作空间要求，实测超过限位/碰撞会收窄。

### D3. 机械间隙与可维护性

- 对每个关节定义扫描用 clearance envelopes；腿摆动全行程不能与邻腿、躯干、地面卡死。
- 每段必须可从工作台检验属于哪个 Sable UUID；任意两个刚体不可通过胶直接粘成不受控环。
- 不要随意把所有腿关节做成封闭刚性闭环；多约束冲突易导致 Sable solver 不稳定。
- 构建先采用标定靶/可视轴线辅助贴图。装配前跑几何与可达检查，通过后才开展动态测试。
- 受损/维修流程必须考虑重力：拆掉承重关节后整机可能真实倒地；不能指望恢复蓝图就自动恢复原 pose。

## E. 装配工艺与功能检测步骤（首架腿测试台）

1. 在隔离测试世界铺设平整测量地板，固定根机架；固定架要**可见**、被记录为试验工装，不能把固定架测试宣称为无支撑行走。
2. 装配髋外展 carrier 和 HAA 旋转轴；单独验证轴线与旋转方向。断电关节被动阻尼/锁止要可配置。
3. 在 carrier 下组装上腿和 HFE；再将下腿/鞋底通过 KFE 连接；各段单独 Sable UUID 验证。
4. 标定每轴零位与正向，施小幅 ±5° 指令；从真实相对 orientation 读反馈，验证不是仅 UI 目标值变化。
5. 空载逐级测试 10°、25°、最大候选角，记录角速、响应时间、过冲、约束反力/饱和/块间碰撞。
6. 连上真实可承重质量块，并在足底放载荷台；逐级提高质量，达到额定极限应堵转/失速而非飞天。
7. 加足底触地/接近反馈，执行抬脚→摆动→触地→加载的完整周期 100 次。仍使用机架承担其他 3 条腿本应分摊的重量。
8. 单腿通过 G2 才复制四套腿体与各 12 关节；组装后移去试验固定架，开始 G3 的站立闭环测试。

## F. 版本兼容风险

Aeronautics 的 SwivelBearing 源码能读到 targetAngleDegrees 通过驱动 shaft 的 RPM 累计，而不是已公开任意软件设定 angle 的 API。故不可直接声称安装一个普通轴承即可每 tick 跟随 IK：
- M0 先测原生轴承可驱动/限幅的实际行为和读取角；
- 若可选 Servo Bearing 暴露稳定目标角/力矩 API，则编写 JointAdapter；
- 如果不能，必须实现自己的 **MuscleServoBlock**，通过正式 Sable Motor/Constraint API 发送限力指令；不复制第三方闭源源代码。
