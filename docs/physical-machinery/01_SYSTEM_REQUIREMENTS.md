# RPMS-REQ｜系统需求规格说明 SRS v0.1
所有需求是可检验的 SHALL 条款，需求 ID 是长期稳定标识。测试证据尚为空，不代表通过。优先级：P0 首个真正步行闭环，P1 交付必备，P2 扩展型。验证方法 T 测试，A 分析，I 检视，D 演示。

## 1. 真实玩家/工程人员用例

- UC-01 创建：从方块搭建机架/腿/关节/传动，正确组装为多个 Sable SubLevel。
- UC-02 校准：逐个轴定位零位、机械行程、转动正方向、动力来源与物理部件。
- UC-03 站立：驱动腿抵抗重力，脚板真实接地，负载/姿态反馈闭环。
- UC-04 行走：玩家输入目标速度，计算落脚点/IK/力矩，四足步行而不是模型拖动。
- UC-05 异常：断开动力、砸断脚、Sable 失去部件 UUID，自动停止危险的关节命令并可自然摔倒。
- UC-06 Boss：PEAK 可抓住真实活动机体，破坏关节/器官导致运动退化；HP 结构基准不可被额外积木刷高。
- UC-07 工程台：实时读传感器/控制值/性能，保留可重复测试报告。

**验证 vs 验收**：JUnit 能证算法正确，GameTest 能证物理世界功能，真人录像能证操作与观感；三个证据不能互相代替。NASA 系统工程手册把需求验证矩阵和用户验证矩阵分别管理，此项目也执行同样的分离。

## 4. 需求变更流程

每项变更提交 CR-编号、受影响需求 IDs、接口/物理版本、BOM、成本(开发/性能)、风险和测试变化；批准后生成新文档 revision，保留原门禁判据。生产分支只接受附有证据的 PR；规划可单独 Draft PR。
