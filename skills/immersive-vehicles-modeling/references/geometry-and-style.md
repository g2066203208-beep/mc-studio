# 造型研究与原创低多边形制作规则

## 风格：从可观察的几何结构归纳，而不是“方块越多越像 MC”

- **先认出车辆，再看到细节**：侧面 256px 缩略图必须读得出轮距、乘坐区、前后比例、发动机/车身主量块；若看不出型号类别，停止做小灯和仪表。
- **大块平面 + 有意的折线**：车顶、油箱、挡泥板沿主要形面组织顶点，轮拱/护板用少量分段近似曲率；避免高模汽车 CAD 的光滑圆角和通篇微小方盒镶嵌。
- **精度分配**：轮子、车把/转向/车灯、曲轴/传动/排气出口、踏板/脚撑优先保证位置；不影响远景的螺丝贴图优于加多个真实圆柱。
- **UV 像素纪律**：使用清晰像素块、限制颜色数量、避免随机照片纹理和模糊边缘。按视觉权重给油箱/车门/车头更多 atlas 面积。贴图匹配模型 UV，PNG 的路径和尺寸必须在完整模型而非 inventory icon 上核对。
- **轴向可验证**：以当前官方 Mustang 为例：轮对在 X 两侧，前轮偏 +Z，向上 +Y。新车可沿该约定制作，但不能未验证就假定每个 MTS 包同一坐标。
- **几何与行为分开**：OBJ 只放可见几何与命名对象。轮胎/引擎/座椅是否单独安装，应按照所选 MTS pack 版本定义，不能先在主体 OBJ 画死又重复安装。
- **展示必须忠实**：至少 3/4、严格侧面、严格正面、俯视；线框/无贴图检查轮廓。检查背面消失、穿透、重叠 Z-fighting、拉伸 UV、错误透明排序。

## 以原创摩托车为训练项目（非直接复制沉浸车辆的品牌车）

**原则：结构决定形象，取消无意义装饰。** 先选车种（街车/越野/巡航），一次只做**一辆**，不要同时造五种车或擅自添加夸张军用设备。

第一阶段：灰模（可持续重复迭代）
- 前后轮沿车长 Z 轴对齐，X 接近 0；**一根车轮轴线在横向 X 方向**，轮宽和轮圈按原版像素尺度做低多边形环。
- 以轮距作为无量纲尺度（例如规范化为 1.0）：定义车轴中心高度、油箱最高点、座椅坐高、前叉倾角、车头与尾部外伸。下面数值只是**原创设计起始比例，不是官方规格**：轴距 1.0、轮外径 0.36–0.43、座高 0.45–0.53、把手高 0.60–0.70。按实际 MC 玩家骑姿再调。
- 核心对象拆开：车架、油箱、座垫、前叉、后摇臂、发动机体块、排气管、车灯、刹车/尾灯、车把、前后轮插槽、转向枢轴；如果游戏中轮子独立安装，则网页必须把未安装状态标明。
- 检查前叉转向轴、前轮回转中心、座椅落点和玩家双手握把高度。仅视觉看起来像摩托车，不代表操作物理成立。

第二阶段：风格化材质
- 先分 **车漆主色 / 深色橡胶 / 金属框架 / 灯与玻璃 / 座垫** 5 类大材质块。
- 一张 atlas 起步；测试在游戏目标缩放下像素锐利度；透明玻璃和发光灯光分别验证。不要为了“高级感”加入车身磨损、徽章或多余外挂，除非用户指定。
- 同系列涂装通过更换 PNG，而非按配色复制一份完全相同 OBJ。

第三阶段：可交互模型
- 车把/前叉可作为转向动画组；车轮、避震、刹车把、脚撑可拆对象或引擎部件，依据 MTS 具体功能支持实现。
- 先验证静态放置、安装轮胎和玩家坐姿；再验证载人转向、碰撞、动态音效/灯光。**不猜引擎 JSON 字段；以相同版本的可运行数据定义为准。**

## 本项目审美门槛

**必须问自己：** 从侧面一眼是不是正常的交通工具？是否能区分车架、油箱、座椅、前叉、前后轮？有没有穿模、漂浮零件、车轮不着地？实际贴图是否像 Minecraft 干净有层次的低多边形模型？  
若不满足，**先返工主体比例**，不要靠截图滤镜、复杂灯效或更多零件掩盖。

交付首次灰模之后让用户评估**真实可旋转网页里的比例**，反馈达标后才做精细贴图、可驾驶逻辑。
